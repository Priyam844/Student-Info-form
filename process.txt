================================================================================
PROCESS.TXT  --  How this Django + Supabase project works
================================================================================

PROJECT: Student records app (name, phone, email, student ID, address and more)
DATABASE: Supabase Postgres (falls back to local SQLite until you add credentials)

--------------------------------------------------------------------------------
1. THE PROCESS WORKFLOW (what happens, step by step)
--------------------------------------------------------------------------------

STEP 1 - SETUP (once)
  pip install -r requirements.txt
  copy .env.example  ->  .env   (fill in your Supabase connection string)
  python manage.py makemigrations students
  python manage.py migrate

STEP 2 - USER OPENS THE SITE
  Browser  ->  http://127.0.0.1:8000/
  Django receives the request in config/urls.py and sends it to
  students/views.py :: student_list.

STEP 3 - USER FILLS THE FORM  (POST /students/new/)
  1. Django renders students/forms.py :: StudentForm (fields come from the
     Student model in students/models.py).
  2. User submits. Django runs validation:
        - required fields (name, email, phone, student ID, address)
        - email format + email must be unique
        - student ID must be unique
        - phone must match the phone regex
  3. If invalid  -> the form is re-rendered with red error messages (no DB write).
     If valid    -> form.save() is called.

STEP 4 - SAVING TO THE DATABASE (Supabase)
  form.save()  ->  Django ORM (students/models.py :: Student)
               ->  SQL INSERT is generated by Django
               ->  psycopg2 driver sends it over TLS/SSL
               ->  Supabase Postgres (session pooler / direct, port 5432) writes the row
               ->  row now lives in the "students_student" table in Supabase.
  settings.py builds the connection from SUPABASE_DB_URL in .env.
  If SUPABASE_DB_URL is missing, Django uses local db.sqlite3 instead,
  so you can develop before you have Supabase credentials.

STEP 5 - READING DATA BACK
  GET /  ->  Student.objects.all()  ->  SELECT * FROM students_student
          ->  rows come back from Supabase  ->  rendered into student_list.html.
  GET /students/<id>/  ->  one row (student_detail.html).
  Search box (?q=...) -> Django turns it into a SQL WHERE ... LIKE query.
  DELETE button        -> SQL DELETE (after a confirm page, POST only).

STEP 6 - ADMIN
  /admin/  (superuser) shows the same table for CRUD without writing code.

3. WHAT YOU NEED TO CONNECT SUPABASE
--------------------------------------------------------------------------------

REQUIRED
  1. A Supabase account + a project  ->  https://supabase.com (free tier is fine).
  2. The Postgres connection string (URI). Find it at:
        Supabase Dashboard -> top bar "Connect" -> Direct (connection string)
        -> section "Session pooler" -> copy the URI
     Session pooler looks like:
        postgresql://postgres.YOUR_PROJECT_REF:YOUR_DB_PASSWORD@aws-0-REGION-N.pooler.supabase.com:5432/postgres
     Direct connection looks like:
        postgresql://postgres:YOUR_DB_PASSWORD@db.YOUR_PROJECT_REF.supabase.co:5432/postgres
  3. Your database password (set when the project was created; resettable in
     Project Settings -> Database).
  4. These values written into a .env file in the project root:
        SUPABASE_DB_URL=postgresql://postgres.XXXX:PASSWORD@...:5432/postgres
  5. Python packages from requirements.txt: Django, psycopg2-binary, python-dotenv.

WHICH CONNECTION STRING TO PICK (from the "Connect" dialog)
  * Session pooler  (aws-0-*.pooler.supabase.com:5432) -> USE THIS ONE.
    Works on any network (IPv4), supports prepared statements and session
    state, and handles Django's migrations / admin / runserver.
  * Direct connection  (db.*.supabase.co:5432) -> OK if your machine speaks
    IPv6 or the project has the IPv4 add-on; otherwise it times out.
    Supabase also recommends it for one-off commands (pg_dump, backups).
  * Transaction pooler  (*.pooler.supabase.com:6543) -> NOT for Django.
    No prepared statements, session state lost between transactions, so
    `python manage.py migrate` fails.

SECURITY / NETWORK NOTES
  * sslmode=require is the default in settings.py (Supabase requires TLS).
  * If your password contains special characters (@ # ? % / :), URL-encode them
    in .env:  @ -> %40, # -> %23, ? -> %3F, % -> %25, / -> %2F, : -> %3A
  * If the connection times out: your network is probably IPv4-only, so use
    the Session pooler URI (or enable the IPv4 add-on for the direct URI),
    and check no IP/network restriction blocks your machine.
  * Keep .env out of git (.gitignore already lists it). Never commit passwords.
  * For production, run gunicorn and set DJANGO_DEBUG=False + a real
    DJANGO_SECRET_KEY.

NOT NEEDED FOR THIS PROJECT
  * The anon key / service_role key and the https://XXX.supabase.co URL are for
    the Supabase JS/Python client libraries (PostgREST, Auth, Storage).
    Django talks directly to Postgres, so only the connection string matters.

--------------------------------------------------------------------------------
4. COMMAND CHEAT SHEET
--------------------------------------------------------------------------------
  pip install -r requirements.txt          install dependencies
  python manage.py makemigrations          create migration from models.py
  python manage.py migrate                 apply migrations to the DB
  python manage.py createsuperuser         admin login for /admin/
  python manage.py runserver               start dev server (http://127.0.0.1:8000)
  python manage.py test                    run the test suite
  python manage.py shell                   interactive Python with the ORM

FIRST RUN WITH SUPABASE
  1. Fill .env with SUPABASE_DB_URL.
  2. python manage.py migrate      <- creates the tables inside Supabase.
  3. python manage.py createsuperuser
  4. python manage.py runserver
  5. Open http://127.0.0.1:8000/students/new/ and add a student.
  6. Check the row appeared: Supabase Dashboard -> Table Editor -> students_student.
